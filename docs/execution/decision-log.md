| D-001 | 2026-08-06 | Recommended | Use **RoleDawn** as the working brand. | Distinctive, owns the overnight mechanism, and passed preliminary exact-name/domain screens. | Legal trademark review or user research finds confusion, awkward pronunciation, or weak recall. |
| D-002 | 2026-08-06 | Accepted | Position around trust and verified outcomes, not maximum application volume. | Volume is easy to copy and amplifies ATS, support, and reputation risk. | Cohort data proves a different promise produces materially better retention and interviews. |
| D-003 | 2026-08-06 | Accepted | Target an iPhone-first active-search state; use early-career as the wedge without making age the brand. | Channel behavior and acute pain are more useful than a generational label. | Research shows another cohort has much higher urgency, willingness to pay, and fit. |
| D-004 | 2026-08-06 | Accepted | iMessage is a control surface, not the canonical UI or system of record. | Long diffs, sensitive fields, portability, and provider risk require a secure web surface. | Apple provides a suitable direct server API and users consistently prefer messaging for complex review. |
| D-005 | 2026-08-06 | Recommended | Pilot iMessage through Photon behind `ChannelAdapter`; keep web/SMS fallback. | Fastest path to a realistic alpha without making vendor semantics architectural. | Photon diligence fails platform, security, portability, or reliability requirements. |
| D-006 | 2026-08-06 | Accepted | Do not run a permanent general-purpose agent or container per user. | Durable logical state plus on-demand workers is safer, cheaper, and easier to version and observe. | A measured workload requires dedicated isolation for a regulated or enterprise tier. |
| D-007 | 2026-08-06 | Accepted | Do not use Hermes as the production control plane. | Broad tools and agent-managed memory conflict with deterministic policy, tenant isolation, and audit. | A pinned sandboxed executor beats purpose-built workers in a controlled evaluation. |
| D-008 | 2026-08-06 | Recommended | Use Temporal for one durable workflow per application. | Applications span hours or days, wait on people, and require safe retry/reconciliation. | A simpler queue implementation meets the same tested durability and recovery requirements at materially lower complexity. |
| D-009 | 2026-08-06 | Accepted | Browser automation is the universal MVP execution path; formal ATS partnerships are the moat roadmap. | Public ATS APIs expose jobs, while arbitrary candidate submissions usually require employer or partner credentials. | A verified candidate-authorized direct submission standard emerges. |
| D-010 | 2026-08-06 | Accepted | Require final-submit approval for every MVP application. | Trust, legal attestations, and unreliable terrain make silent autopilot premature. | A validated adapter and explicit bounded standing authorization meet rollout gates. |
| D-011 | 2026-08-06 | Accepted | Exact/sensitive facts come from structured, approved records; embeddings are supporting retrieval only. | Similarity search is not a safe authority for identity, dates, work authorization, or legal answers. | Never; implementation details may change, the invariant does not. |
| D-012 | 2026-08-06 | Recommended | PWA first, native mobile after the approval loop is validated. | iMessage plus responsive web tests the core behavior without duplicating product work. | Retention data shows native-only capability is the adoption bottleneck. |

Failed, canceled, uncertain, or duplicate attempts do not count. | This keeps the experiment out of the penny-per-application race and exposes whether measured cost can support at least 65% gross margin at full allowance. | Cost, conversion, utilization, and willingness-to-pay data support a different grid. |
| D-014 | 2026-08-06 | Accepted | Gate all employer logos and outcome claims behind consent and documented evidence. | Precision is both legally prudent and a brand differentiator. | Never; presentation may change, the truth requirement does not. |
| D-015 | 2026-08-06 | Accepted | PostgreSQL owns durable domain state, Temporal owns in-flight execution history, and the append-only ledger owns consequential proof; synchronize through transactional outbox/inbox and optimistic versions. | Calling multiple stores “canonical” without ownership creates unsafe divergence near approvals and submit. | A tested alternative preserves the same transaction, replay, and repair guarantees. |
| D-016 | 2026-08-06 | Accepted | Build the night shift on an approved official-source registry with stable job identity, incremental polling, freshness/closure metrics, and source-policy controls. | Continuous discovery is a product subsystem, not a search query inside an agent prompt. | Licensed/partner feeds replace specific acquisition paths. |
| D-017 | 2026-08-06 | Accepted | Use “Nothing invented. Nothing outside your rules.” as the durable trust line; use “Nothing submitted without your approval” only while per-application approval is the actual product. | Future standing authorization would make “nothing sent unseen” false even if it remains inside explicit user rules. | Product permanently commits to pre-send visibility for every application. |
| D-018 | 2026-08-06 | Accepted | Model messaging-provider resources separately from verified user channel bindings; do not provision one iMessage line per candidate by default. | A project line or bounded pool can serve many users, while identity and consent remain internal RoleDawn records. | A provider or platform contract requires one dedicated resource per user or a tier needs isolated identity. |
| D-019 | 2026-08-06 | Accepted | Keep prompts, tool grants, model routes, and policies in centrally promoted immutable versions; expose only bounded product preferences to tenants. | Raw per-tenant agent configuration creates unreviewed authority, quality drift, and unreplayable behavior. | An enterprise control is expressible as a tested, typed policy without expanding model authority. |
| D-020 | 2026-08-06 | Accepted | Parse each public job version once, retrieve potentially eligible searches with indexed hard dimensions, run exact rules, then perform bounded reranking and draft only admitted top-K items. | This prevents a model-scored jobs-by-users cross product and reserves cost for likely queue items. | Measured retrieval quality or scale requires a different index while preserving bounded work. |
| D-021 | 2026-08-06 | Accepted | Domain records store opaque credential references; a dedicated broker owns OAuth tokens and issues narrowly scoped short-lived access to workers. | Tokens do not belong in prompts, ordinary database rows, browser logs, or tenant-editable connector configuration. | A managed connector proves an equivalent or stronger audited boundary. |
| D-022 | 2026-08-06 | Accepted | Defer Gmail OAuth until the core Career Vault → approval → submission receipt loop proves value; start with no mailbox access. | Gmail adds verification, privacy, support, and possibly restricted-scope assessment burden before the core product is validated. | Recruiter follow-up or confirmation reconciliation shows measured value that cannot be met by forwarding or user-provided messages. |
